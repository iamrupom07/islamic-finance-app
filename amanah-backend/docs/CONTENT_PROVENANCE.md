The Bengali translation probe returned text that could not be tied to the current publisher version list/download metadata. It is excluded; the app does not label it as a verified Rowwad Bengali edition. Bangla interface translation is separate from religious-source translation. A future Bengali edition requires a complete licensed source, version, transcript, identifiers, counts and a new reviewed content lock.

SHA256s in SOURCE_RECORDS.json document retrieved input files. The independent edition lock pins the assembled payload and every surah; runtime and CI reject mismatches. These are integrity/compatibility checks, not an independent scholarly judgment. Publisher verification statements are attributed to the publisher; no Amanah reviewer approval is invented.

To update content, stage source files from the publisher, preserve text/footnotes/context and notices, check complete identifiers/counts and record usage permission. Review the candidate, assign a new edition, then regenerate payload/per-surah hashes and its lock in both component directories. Update the canonical-count contract only for an explicitly supported numbering system. Run both projects’ content/contract/regression checks and rebuild the app. Do not change approved flags or hash metadata to make an incomplete edition pass. Never enable a Dua recording without edition/item identity, reciter, exact source, rights and allowed download/stream uses.

`pnpm content:updates` in the backend checks the publisher’s installed translation version without changing content. The root scheduled workflow requests review when it changes; it never automatically approves/replaces text. Review Tanzil updates and recording permissions separately. The current audio source HEAD checks cover first/last surahs for both selected reciters and establish availability/type, not a manual listening review of all recordings.
