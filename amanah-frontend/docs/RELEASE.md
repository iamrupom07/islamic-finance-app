# Native release and device verification

Use the supplied `.env.example`; only public API and legal/native identity values belong in the mobile build. No PostgreSQL, Upstash, provider or cloud service-account secret is used by this app. Copy the exact official Amanah icon to `assets/brand/official-icon.png`, document its rights, and configure real package IDs and EAS project ID. No substitute logo is generated.

1. Run `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm api:check`, `pnpm content:verify`, `pnpm routes:check` and `pnpm format:check`.
2. Import the reviewed content JSON using `node scripts/import-content.mjs /absolute/path/approved.json`. The bundle must include source/edition/license/reviewer metadata and an independently reviewed SHA256. Install the identical bundle on the API. Structural/hash validation does not itself establish textual accuracy or legal permission.
3. Configure development/preview/production EAS environments, real Android/iOS identifiers and HTTPS API URL. Configure native Google audiences and signing fingerprints. The mobile hides Google on iOS unless an equivalent Apple sign-in option is configured. Apple sign-in uses a one-time backend-issued nonce. Account linking by matching email is deliberately disabled; existing users use their original sign-in method.
4. Build a native development client with EAS or local Xcode/Android Studio. SQLCipher and native sign-in must be tested in native builds. Before writing a financial snapshot, the app checks `PRAGMA cipher_version`; without encryption support it disables the persistent financial cache. Mutations are never queued offline. Home, reports, prayer and first list pages may use account-scoped encrypted snapshots.
5. Test two separate accounts on actual Android and iOS devices, 320dp/393dp/tablet widths, 200% text, light/dark/system, English/Bangla, Arabic RTL, keyboard/back/swipe behavior, denied permissions, cold starts, 429/503, offline, expired access and rejected refresh. Screen render tests and JS bundles are useful evidence but are not device QA.
6. Test income/expense/Sadaqah, manual and metal assets, debt correction/settlement, complete/partial zakat records, immutable history, method/city change, reminders after device timezone changes, bookmarks/favorites, export, sign-out/cache purge and in-app account erasure. Require explicit confirmation for destructive requests. Verify all displayed amounts and source timestamps against staging.
7. Exports are explicit private downloads to the device cache and are deleted after the native share sheet closes. Lingering export files are also removed on foreground/startup/logout. The chosen share destination becomes the user's responsibility.
8. Prayer reminder scheduling is local and finite: validated upcoming days only, refreshed when the app is active. Missing/stale data never creates guessed reminders. OS power policies may delay delivery; the app requests no unrestricted exact alarms. Weekly and anniversary reminders contain no financial values. Changing location/method or signing out removes old reminders.
9. Configure actual legal URLs/support and a reviewed retention policy. Active account erasure cascades personal records; encrypted backups and pseudonymous audits follow the operator's documented retention period. Do not claim instant backup erasure. Rehearse restore/deletion replay before release.
10. Run `pnpm release:check`, then `eas build --profile preview --platform android` and the iOS preview profile. Complete staging/device acceptance and store policy review before a signed production build. No cloud/EAS deployment or store submission occurred in the coding environment.

Fonts are bundled locally with their license files. Outfit uses regular/medium weights; Amiri and Noto Sans Bengali handle script shaping. No continuous animation is required; loaders and sheets work with reduced-motion settings.
